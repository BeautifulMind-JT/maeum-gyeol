# 계정 전환·저장 안전성 개발 기록

작성일: 2026-09-14. 사용자 요청에 따라 배포 검증과 분리 가능한 개발을 먼저 진행한다. 운영에서 사고가 발생했다는 조사 결과가 아니라, 합성 데이터로 재현한 코드 결함의 수정 기록이다.

## 기준과 범위

- GitHub 기준: `main`의 `9ed2af3824c474c3e1cc76378c43a96412736124`. 앱 소스는 부모 `39d79b6afb3b6e186bd0fdee9576cd6ce957b498`에서 이어진다.
- 독립 작업 디렉터리의 수정 전 소스 트리는 앱 기준 트리 `47bd64a814ef6da4b308c625041b926a50e2adca`와 일치한다. 원래 작업 디렉터리의 사용자 변경은 수정하지 않았다.
- 수정 파일: `mobile/src/main.mjs`, `mobile/src/server-journal.mjs`. DB·RLS·인증 정책·배포 설정·패키지 버전은 변경하지 않는다.
- 실제 사용자 계정·기록·사진을 테스트 데이터로 사용하지 않는다. 운영 승격은 이번 작업 범위가 아니다.

## 수정과 회귀 검사

| 재현한 문제 | 수정 | 검사 |
|---|---|---|
| A의 초안·기록 응답을 기다리다가 B로 바뀌면, A의 내용이 B의 초안으로 전달되거나 화면에 다시 표시될 수 있음 | 비동기 작업 시작 시 저장 인터페이스와 화면 세대를 보관하고, 주요 대기 지점 이후에도 같은 계정·화면인지 확인 | `tests/account-transition.test.mjs`: 이전 계정 응답 4개, 같은 계정의 오래된 화면 이동 2개, 정상 동작 2개 |

| 동기화 결과가 응답 미확인 요청이 있어도 대기 0개로 보고함 | 실제 잔여 요청 수 반환. 새로고침으로 재전송·삭제하지 않음 | 대기 집계 1개 |

UI 회귀 검사는 실제 `main.mjs`의 계정 전환·화면 진입·초안 저장 함수를 VM에서 실행한다. DOM·브라우저 기본 기능과 저장 인터페이스는 대역이다. 저장 큐 검사는 실제 `server-journal.mjs`와 결정적 전송 대역을 사용한다. 둘 다 실제 브라우저나 Supabase 종단 간 검사를 대신하지 않는다.

## 로컬 검증

- 수정 전 새 회귀 검사 13개 중 11개 실패, 정상 흐름 대조군 2개 통과. 수정 후 새 검사 13개 통과.
- `npm test`: 기존 42개 + 신규 13개 = 55개 통과. 기존 DB 검사는 로컬 PGlite 기반이다.
- `npm --prefix mobile test`: 4개 통과.
- `npm run build:production`: 성공. Node `24.19.0`, 기존 잠금 파일과 일치하는 설치 의존성을 사용했다. 이번 로컬 검증에서 신규 `npm ci`를 수행한 것은 아니다.
- `node scripts/check-source.mjs`: 로컬 추적 파일 212개에서 검사 패턴에 해당하는 자격 증명·서명 자료 없음. 모든 비밀 정보 부재를 보증하는 검사는 아니다. `git diff --cached --check`도 통과했다.
- GitHub CI 실행 상태와 결과는 해당 개발 PR의 Checks를 기준으로 별도 확인한다.

## 남은 확인

- 새 체크아웃·고정 환경의 잠금 의존성 설치, 실제 PostgreSQL·PostgREST API 검사와 산출물 목록 생성은 기존 M0 PR CI가 담당한다. 로컬에서 실제 PostgREST 12개 검사를 수행했다고 주장하지 않는다.
- 실제 이메일 로그인, 계정 전환, 사진, 실폰·재접속 흐름은 미검증이다. 새 UI 검사는 오프라인 경계 검사이며 실제 사용성·데이터 보존 전체의 증명이 아니다.
- 기존 후보 배포에는 이번 변경이 없다. 변경 코드를 운영에 반영하려면 해당 커밋의 새 산출물·후보 배포를 별도로 검증해야 한다.
- M0·M1·M2 전체 완료 상태는 올리지 않는다. 기준과 배포 보류 맥락은 [M0 재개 기록](M0-RESUME-2026-09-14.md), 개발 범위 조정은 [블루프린트 16절](BLUEPRINT.md#16-배포-검증과-분리한-개발-병행)을 따른다.
