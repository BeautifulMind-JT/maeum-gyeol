# M0 실행 명세

제품과 M0–M5의 기준 문서는 [BLUEPRINT.md](BLUEPRINT.md)다. 이 문서는 0.7.1 구현의 구체적인 재현 절차와 검사 환경을 설명한다. 실행 성공의 근거는 해당 커밋의 CI와 배포 확인 결과다.

## M0 실행 조건

1. GitHub 특정 커밋을 새 환경에서 체크아웃하고 Node 24.19.0과 두 lockfile로 설치한다.
2. 운영에 적용된 SQL 원문과 저장소 세 파일의 SHA-256 대응은 migration-map.json에 남긴다. 번호가 다르다는 이유로 운영 이력을 수정하거나 SQL을 재적용하지 않는다.
3. 새 PostgreSQL 17.6에 사전 조건 SQL과 세 마이그레이션을 실행한다. 테이블·열·함수·트리거·정책·권한·사진 버킷 설정의 266개 카탈로그 항목을 운영에서 읽어 보관한 스냅샷과 비교한다.
4. 고정된 관계 구조와 seed.sql에서 PostgREST 16.3을 실행한다. 기존 조회 네 개가 PGRST201로 실패하고 실제 클라이언트의 수정 조회가 정상 동작해야 한다. 빈 결과와 공개 글·작성자·상세·대표 기록·댓글 작성자, 비공개 접근 거절을 확인한다.
5. 운영 공개 설정으로 빌드한다. 파일 전체 목록·크기·SHA-256을 release-manifest.json에 기록한다. 업로드 목록과 대조하고 누락·추가·변경 파일을 확인한다.
6. 배포의 고유 주소와 공식 주소를 확인한다. HTTP로 제공되는 파일은 압축 해제 후 바이트를 대조하고, vercel.json 같은 배포 제어 파일은 업로드 및 배포 설정에서 따로 확인한다. 플랫폼의 원격 전체 목록을 얻지 못했다면 추가 파일 검사는 미확인으로 남긴다.

## 검사 환경의 범위

CI의 DB는 매 실행 새로 생성하는 실제 PostgreSQL이다. prerequisites.sql은 앱이 참조하는 auth.users/auth.uid 및 storage 테이블의 최소 인터페이스다. 실제 OTP 발송, 세션 발급 서비스, Storage HTTP·사진 바이너리 서비스를 실행하지 않는다. 이 부분을 M1·M2 검증으로 계산하지 않는다. 운영 DB에는 시험 데이터를 쓰지 않는다.

카탈로그 비교에서 PostgreSQL 18의 독립 NOT NULL 제약 표기는 제외하지만 열별 nullable을 반드시 비교한다. 운영과 CI의 PostgreSQL 버전은 모두 17.6이며, 로컬 PGlite는 보조 검사다.

## 배포와 복귀

일반 Preview를 Production으로 승격하면 운영 설정으로 재빌드될 수 있다. 운영 설정으로 만든 staged production은 도메인 연결 시 재빌드하지 않는다. 정적 파일 업로드 방식이라면 후보에서 확인한 동일 파일을 재빌드 없이 운영에 보내고 전체 바이트를 재대조할 수 있지만, 동일 배포 ID를 승격한 것과 구분해서 보고한다.

현재 M1·M2를 통과한 복귀 기준 배포는 미확보다. 예전 0.7.0에는 발견 오류가 있으므로 자동으로 정상 복귀 대상으로 지정하지 않는다. 배포마다 검증 범위·남은 결함·호환 DB 이력을 적는다. M0 이후에도 실제 이용 미검증을 표시하고, M1·M2까지 통과한 배포를 이후 변경의 복귀 기준으로 삼는다.

장애 때는 추가 배포를 멈추고 영향 범위·현재 배포·요청 실패를 확인한다. 호환성과 해당 장애 회피가 검증된 후보가 있을 때만 전환한다. 후보가 없으면 미확보 상태를 알리고 수정 후보를 검증한다. 웹 롤백을 이유로 DB 변경을 자동으로 되돌리지 않는다.

## M1·M2 검사 목록

이메일 OTP, 연습 중단·재개, 비공개 글·사진, 서버 초안, 종료·재접속, 다른 기기, 수정·사진 교체, 공개·상세, 공개 철회, 삭제·오래된 요청, 응답 유실·동일 요청 재시도, 동시 수정, 사진 부분 실패, 계정 전환, 서비스 워커 업데이트, 계정 삭제·레거시 이전을 실제 시나리오로 확인한다.

공개 철회는 B 계정이 공개 당시 확보한 사진 요청 URL로 철회 후 새 다운로드를 시도해도 차단되어야 한다. 현재 코드는 비공개 버킷에서 권한을 검사하는 download 요청으로 Blob을 받아 표시하며 서명 URL을 발급하지 않는다. 실제 HTTP 경로는 M2에서 확인한다. 이미 받은 Blob/화면/외부 사본의 원격 회수와 서버의 새 접근 차단을 구분한다. A의 비공개 원본은 유지한다.

## 완료 보고

커밋·변경 목록, 고유 배포·공식 주소, 전체 파일 비교의 범위와 결과, 실제 실행한 검사와 실행 환경, 미확인 항목·남은 결함, 복귀 대상 및 호환 DB 상태를 함께 보고한다. CI 통과를 실제 이메일 로그인·사진 저장의 성공으로 바꿔 표현하지 않는다.
